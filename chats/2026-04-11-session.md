### 3. PostgREST Pagination Fix (Critical Bug)
- **Root cause**: Supabase PostgREST has a server-side 1000-row cap. `.limit(10000)` in supabase-py does NOT override it.
- **Impact**: Cashflow and KPI queries silently truncated results when querying multi-year ranges (2024-2026 = ~2100 invoices). This caused 2025 data to appear as $0 invoiced.
- **Fix**: Created `fetch_all()` pagination helper in `backend/main.py` that loops in 1000-row pages using `.range(offset, offset+999)`. Applied to cashflow, kpis, and 10+ other endpoints (dashboard, exceptions, aging, customers, reconciliation items, periods).

### 4. YTD Date Range Fix
- Bug: YTD for past years used today's date (YTD 2024 = Jan 2024 to Apr 2026)
- Fix: If `year < currentYear`, YTD returns `Jan 1 - Dec 31` of that year. Current year still uses today.
- File: `frontend/src/pages/Dashboard.jsx`, `presetRange()` function

### 5. Custom Date Range Capping
- Added `min` and `max` HTML attributes to custom date picker inputs
- Capped to actual data range (min_date from 2024-01-01, max_date from 2026-03-31)
- Cross-capped: From's max = current To value, To's min = current From value

### 6. Sticky Sidebar + Theme Toggle Visibility
- Problem: Theme toggle at sidebar bottom was pushed off-screen on pages with tall main content
- Fix: Made `.sidebar` sticky (`position: sticky; top: 0; height: 100vh; display: flex; flex-direction: column; overflow: hidden`)
- Added `.sidebar-nav` class with `flex: 1; overflow-y: auto` for scrollable nav
- Removed inline styles from Layout.jsx
- Mobile CSS (`position: fixed`) naturally overrides sticky -- no conflict

### 7. GL Double-Entry Fix (Variance Issue)
- **Root cause**: Historical data generator only created single-sided GL entries:
  - Invoice: Debit 1200 (AR) only -- missing Credit 4000 (Revenue)
  - Receipt: Debit 1000 (Cash) only -- missing Credit 1200 (AR)
  - Credit Memos: No GL entries at all
- **Impact**: Period Movement table showed massive variances (40-100%) because GL net = invoiced only, while subledger net = invoiced minus collected
- **Fix**: Updated generator to produce proper double-entry:
  - Invoice: Debit 1200 + Credit 4000
  - Receipt: Debit 1000 + Credit 1200
  - Credit Memo: Debit 4000 + Credit 1200
- 2024/2025 variances now 0.0% across all months
- 2026 data (original seed) retains natural variances representing actual reconciliation items

## Architecture Notes

### Stack
- **Frontend**: React 18 + Vite 5 + Recharts + react-router-dom v6
- **Backend**: FastAPI + supabase-py (PostgREST REST API, no direct DB password)
- **Database**: Supabase (PostgreSQL) at `pikdtkqjhsektckwrkkb.supabase.co`
- **Deploy**: Vercel serverless -- `api/index.py` imports `backend/main.py`
- **Theme**: CSS custom properties with `[data-theme="dark"]` overrides, persisted in localStorage

### Critical Gotcha: PostgREST Row Limit
Supabase's PostgREST silently caps results at 1000 rows. `.limit(N)` in supabase-py does NOT override the server-side cap. Must use `fetch_all()` which paginates via `.range()`. This affects any query that could return >1000 rows.

### Data Architecture
- 2026 data (INV-00001 to ~INV-00350): Original seed data, represents "current year"
- 2024-2025 data (INV-10001+): Generated historical data, 20% YoY growth
- GL entries must be double-entry (Debit + Credit) to match the v_reconciliation_summary view's expectations
- The `v_reconciliation_summary` view computes GL net movement from Account 1200 debits minus credits

### Worktree Pattern
Development uses git worktrees at `.claude/worktrees/gracious-merkle/`. The Vite dev server runs from the worktree. Changes must be copied to the main repo for commits. After pushing to master, run `git merge origin/master` in the worktree to sync.
